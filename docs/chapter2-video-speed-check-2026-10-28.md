# 视频时间与仿真速度核查

日期：2026-10-28。范围：离线量测与模拟参数建议；没有重跑或修改仿真，没有创建到达/五状态人工GT，没有连接硬件。

## 1. 结论

现有单例4.8 mm/s是模拟峰值假设，不是实测参数。本次固定视频窗口中，两段单向迁移的10%—90%进展平均速度粗估约0.89—1.38 mm/s。保持现有最小跃度曲线形式时，建议下一版采用名义峰值1.4 mm/s，一格3.2 mm完整运动历时约4.286 s；这只是视频约束的演示参数建议，未应用、未正式标定。旧例保持原样。

关键发现：20261014_112318视频的容器帧率19.261092 fps与主机接收保存帧速率8.113583 fps不同。首末帧容器间隔91.272084 s，接收间隔216.673689 s，按文件播放比接收过程快约2.373932倍。以播放器秒数直接推算会明显高估该片段的接收时间域运动速度。接收时间仍非曝光时间，设备ticks单位仍未知。

## 2. 来源、时间和坐标

- 原始10段工业相机视频本轮全部重算SHA256，与既有资源清单一致；其中9段无时间sidecar，只能保留未验证容器时间。
- 优先核查有完整1759行sidecar的`camera_20261014_112318_257662.avi`。逐行视频帧索引连续，接收时间和SDK帧号严格递增；保存帧间SDK号跳过合计2412个编号，说明不能将保存帧看作无丢失的固定20 fps曝光序列。跳号原因及SDK计数物理语义未单独验证。
- 固定解码630—810帧，共181帧；原生ROI为(1566,2760,570,336)，不缩放、不套照片H。复用已有Otsu和Adaptive阈值基线；Otsu作为主量测草稿，Adaptive作敏感性检查，而非独立重复实验。
- 近似标尺沿用既有网格周期x=118 px、y=119 px及Gerber设计节距3.2 mm。网格patch在液滴上方，底部外推存在透视和畸变误差；当前不是有效视频毫米标定，不能报告真实190/191编号或物理计量精度。
- 所有新Mask均为未审核量测草稿，不是分割GT、状态GT或到达事件参考。

## 3. 量测定义与实际结果

查看全部固定窗口后选取665—715帧向左迁移及715—780帧向右迁移作描述。它们来自同一采集组，不能视为两个独立实物trial；端点位移约1.20和1.78个近似节距，不冒称各为“一格运输”。窗口选择是可见性选择，非预注册性能研究。

每段用头尾5帧质心中位数定义端点，以端点连线投影定义无量纲进展。10%和90%首次上穿分别保存前后帧号与接收时间，采用采样括区，不插值生成精确穿越时刻。以下范围只含采样括区，未包含接收—曝光偏差、空间标尺和Mask系统误差，不是置信区间。

## 4. 与现有平滑仿真的同口径比较

现有运动q(u)=10u³−15u⁴+6u⁵，T=1.875L/v_peak。q=0.1和0.9对应u约0.246636、0.753364，因此10%—90%平均进展速度约为0.842005×v_peak。不能将视频中段平均速度直接与模拟峰值比较，也不能将同一数字直接填入峰值字段。
