# 第二章v2：BTQ/F双层比较协议与科学可归因性审查

日期：2026-10-25。状态：研究协议，尚未执行E4–E7正式扫描。所有现有数值均为SIMULATION开发材料的只读复核，不是实物结果。

## 1. 本轮结论

E0–E3机制验收成立，但现有21份共同观测缓存中，BTQ/F的到达事件及事件时间21/21一致，不能据此声称F具有随机到达性能优势。现有机制夹具只能证明开关能够阻断相应输入，不能证明这些输入在真实液滴或随机仿真中以足够频率发生。

下一步可进入受限的E4/E5协议实现与少量验证，前提是冻结本协议、补齐分层输出和配对检验。暂不进入E6大规模正式扫描，不以扩大重复次数替代机制辨识。

## 2. 共同基础与BTQ/F差异

| 项目 | BTQ与F共同基础 | F增量 / 限制 |
|---|---|---|
| 覆盖门 | eta_target≥0.85，eta_source≤0.08，分母均为液滴Mask面积 | 不引入rho_target强制阈值 |
| W连续窗口 | ≥5帧且≥0.25 s，最大gap 0.18 s，质心跨度0.11 pitch，覆盖率跨度0.15 | 两方法完全相同 |
| Q观测质量 | confidence≥0.2，面积10–100000 px，1个显著连通区域 | 两方法完全相同，置信度尚无真实模型标定 |
| C0公共完整性 | 帧身份/格式/非空/时间/epoch/模拟Applied因果/一次性消费 | 始终开启，不作为消融 |
| S任务空间 | BTQ不加S | F要求合法源/目标空间及目标多边形外容差0.18 pitch；不是距目标中心≤0.18 |
| K运动历史 | BTQ不加K | F使用同一原始历史中的2个过去有效观测，位移上界6dt+0.18，残差上界0.18+6dt；首次历史可通过 |
| 五状态与保护 | BTQ非到达通常Unknown | F可产生Deviation并触发局部Recovery，属于额外控制通道 |

## 3. A层：同输入到达判据比较

科学问题：在相同观测和相同确认窗下，任务空间S和运动历史K能否减少错误到达事件，代价是多少漏确认或延迟？

- 输入：逐字节相同的Mask缓存、帧身份与simulation时间、地图、外部给定任务片段及模拟Applied时刻。教师任务不得由被比较算法的输出改变。
- 方法：BTQ、BTQ+S、BTQ+K、F-arrival（S+K）。共享W、Q、C0、覆盖阈值和窗口参数。输出仅到达事件，不为BTQ伪造五状态。
- 算法入口禁止读取内部位置、速度、独立参考区间或评分结果。独立评分在预测文件封存后执行。
- 每step最多消费一次ArrivalEvent。重复、跨任务或旧帧拒绝保留在日志。历史样本来自相同C0可解析观测，不因某个gate拒绝而选择性重写历史。
- 主要终点：独立支持的正确确认、提前确认、无参考支持确认、漏确认、区间确认延迟。不把全部“无参考更新”自动称为提前更新。
- 分母同时报告计划步骤、具备独立参考步骤、完整随访步骤；Unknown、无预测、未尝试和右删失分别保留。参考数为0时到达召回为NA，而非0或100%。
- 统计单位是共同cache/配对seed，不是帧。未来采用seed级配对差和区组bootstrap区间；当前3开发seed仅描述，不作显著性或优势结论。

验收：缓存hash完全相同；关闭S/K可逐事件复现BTQ；16组合中C0常开，Q/W/S/K互不改变原始输入与时间；正负机制控制均符合预声明；评分读取与算法读取物理隔离。

## 4. B层：完整控制策略比较

科学问题：在闭环反馈、停滞保护和有限恢复共同作用下，两套完整策略的安全性、完成性与耗时如何变化？

- BTQ完整策略与F完整策略使用同一环境参数、配对seed、独立随机流、动作执行延迟、源准备P0、初始状态和预算。
- 允许五状态、Retry和Recovery改变后续运动，因此两方法后续相机输入可以分叉，不能称为同输入比较。
- 当前F的Deviation保护与BTQ的Unknown/Retry路径不同。结果只能归因于完整策略包；若要归因于S/K到达门，须另设共享保护通道的桥接实验，不能靠整体策略差值推断。
- 记录planned_trials、planned_steps、source_prepared、transport_complete、path_complete、正确/错误事件、Retry、Recovery、stop_reason和未尝试步骤。
- transport_complete仅表示运输流程完成。path_complete必须包含源准备和独立参考支持等预声明条件，二者不互换。
- 阶段终止类别互斥：源准备失败、运输中止、流程完成但参考不支持、独立支持的路径完成、基础设施无效。错误更新、重试、恢复、Unknown为并行标签，不挤占终止类别。
- controlled_start只作运输诊断，不能计入端到端源准备成功。未尝试步骤不从计划分母删除。

验收：同seed共享外部随机条件的定义可核查；阶段计数守恒；停止后未尝试数可重算；不以Recovery次数更高或更低单独证明算法更好。

## 5. 已有共同缓存与机制触发审查

现有共同缓存normal、delayed、partial_stall、jitter、dropout、deviation、failure各3个开发seed，共21份。BTQ/F事件及时间全部一致。

- S-only覆盖候选拒绝0次，Q拒绝0次。现有圆形Mask与噪声条件并未充分检验S/Q。
- jitter的K原始拒绝分别24、10、23次，合计57次；在覆盖门、S、Q均通过的候选上K-only拒绝分别21、10、22次，合计53次。但BTQ本身也无法形成W稳定窗，因此事件层没有额外收益。
- partial_stall、deviation、failure共同缓存中两方法均无到达，覆盖门已足以阻断，不能将其成功拒绝归功于S/K。
- jitter端到端3个seed均源准备失败；受控起点运输诊断每方法共3个独立到达参考、0确认、3漏确认、6未尝试，局部恢复超时。须分层报告，不能只看transport_complete。

## 6. E4：目标参数敏感性（拟议，不运行）

先固定源准备P0，只在同输入A层或受控运输诊断中改变目标判据。完整端到端结果另表，不能通过放松源门提高目标算法成绩。

| 实验 | 拟议水平 | 固定项 | 要回答的问题 |
|---|---|---|---|
| 确认时长 | 0.25 / 0.40 / 0.60 s | N=5，eta=0.85，Q/C0/gap/源准备固定 | 稳定性与确认延迟、删失的折衷 |
| 目标覆盖率 | 0.75 / 0.85 / 0.95 | T=0.25 s，N=5，eta_source=0.08 | 部分到达误确认与漏确认的折衷 |
| 最少帧数（必要时） | 5 / 7 / 9 | T=0.25 s与其余固定 | 区分帧数约束与物理时间约束 |

采用单因素而非盲目全组合。有效最早确认时间至少为max(T,(N−1)/fps)，还取决于曝光相位与处理延迟。若帧间隔大于0.18 s，公共gap门使任何W窗都不可达，必须标记结构不可行，不能解释为F性能差或偷偷放宽gap。当前实现不接受低于0.25 s的正式窗口，协议不要求绕过这一限制。

每条件先输出可行性诊断：覆盖候选数、最长连续窗、帧数/时长上界、Q/S/K拒绝数、独立参考数、随访长度、源准备失败数。若全部失败，先按这些原因分解并回查日志，不为得到“漂亮曲线”事后改阈值或删seed。

验收：一次只改声明参数；预测不读GT；固定缓存/源门hash一致；所有失败能落入可重算类别。此阶段不设置“F必须胜出”的性能门槛。

## 7. E5：独立参考敏感性（拟议，不运行）

在预测和控制日志冻结后，单独改变ReferenceSpec重新评分，不重跑运动或算法。参考来自模拟内部位置、真实模拟速度及连续驻留，不来自Mask覆盖或算法阈值。

| 参考量 | 拟议水平 | 基准 |
|---|---|---|
| 目标中心半径 | 0.06 / 0.09 / 0.15 pitch | 0.09 |
| 最大真实模拟速度 | 0.03 / 0.06 / 0.12 pitch/s | 0.06 |
| 连续驻留时长 | 0.05 / 0.15 / 0.25 s | 0.15 |

以上为待冻结的候选设计，不是已生成结果。分别单因素评分，记录reference版本、原始truth/预测/控制hash。参考连续性不跨epoch、Recovery目标切换或数据断档拼接。

对于独立参考区间[l,u]与首次确认c：c<l为提前；l≤c<u为时间分辨率内不确定；c≥u为有参考支持，延迟区间[c−u,c−l]。主图显示延迟区间或预声明上界定义，不混用参考中点与上界。

没有参考事件的确认标为unsupported；若随访在参考可能出现前终止，不凭空构造反事实参考时间。完整随访而无确认属于miss，随访不足属于right_censored，完全未进入运输属于unattempted。物理不达、预算截止和基础设施缺数据单独记录。Unknown与无预测不删除。可预声明确认随访H=0.25/0.50/1.00 s，分别统计完整随访与删失；不能默认控制导致的删失是非信息性。参考改变导致的类别变化逐事件输出。

验收：仅评分文件改变；预测/控制/truth hash不变；手算区间边界、无参考、重复事件、漏事件、右删失与未尝试用例通过。结果不宣称是实物到达真值敏感性。

## 8. 执行边界、种子与后续准入

开发seed 262000–262002只用于机制调试，不混入未来正式推断。拟议确认seed 263000–263019仅在设计/代码/配置冻结并获准后使用，目前未启动。任何新随机条件记录独立world/camera/executor流及版本，禁止选择F获益seed。

正式扫描前要求：A/B层入口明确；公共完整性常开；源/运输/路径计数守恒；共享cache可复算；参考评分与预测隔离；正常负对照不因开关意外改变；机制可行性与候选触发率足以回答问题。若BTQ/F仍相同，应如实报告增量在该条件下不可识别，而非无限扩大样本寻求优势。
