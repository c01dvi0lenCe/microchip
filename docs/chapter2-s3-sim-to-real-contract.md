# 第二章S3仿真—实物对应协议

版本：1.0；审查日期：2026-10-26。类型：只读源码、已保存数据与接口审查。

## 1. 审查结论与边界

S3可以支持简化二维单液滴视觉闭环**算法**的比较，不能直接提供实物电润湿动力学精度、真实分割精度或实际高压安全性的证据。可迁移的是任务身份、因果检查、连续证据、事件消费、有限控制预算及独立评分的设计语义；模拟观测、时钟、运动响应和内部真值需要由真实输入与独立计量替代。

本次不修改算法、配置、模型、seed或数据，不启动G4、不连接相机或串口、不进行推理和真实高压实验。S1/S2、120条开发记录和磁盘中已经存在的S3正式结果均只读保留。当前已有G3/G5报告与800条正式记录，因此本文件是追加的可对应性审查，不是重新发放运行批准，也不重建过去的实验。

真实接口未齐备不构成算法仿真的否决理由。只有仿真内部的算法定义、公共输入、公平性、随机源、评分、分母或可追溯性问题，才属于A类仿真协议阻断项。实物准备与启动前验证见配套文件《第二章实物实验就绪性审查》。

## 2. 运行链与信息隔离

仿真运行链：

`外生随机数组 → DropletWorld → SyntheticCamera → ObservedFrame/Mask → 公共特征管线 → 到达门及状态 → P_B/P_F → request → pending → 模拟Applied → World后续响应`

独立评分支路：

`World内部位置/速度/激励历史 → 独立参考分段 → Request/Applied分别评分 → 全计划trial/step统计`

实物对应链：

`真实AM-DMF芯片 → 工业相机/SDK → FramePacket → 经验证分割器 → Mask/图像坐标 → 已绑定标定与地图 → 观测特征/状态/到达事件 → 控制器 → BEGIN/SET/COMMIT → ACK:seq:APPLIED`

独立计量支路：

`原始视频及人工到达区间 + 独立电气输出记录 + 时钟对齐及误差 → 真实评价`

评分真值、人工参考、实物电压记录均不作为算法的在线输入。外部DC_PULSE/VREF记录实验条件，不经上位机自动调压。模拟Mask不是U-Net推理结果，二维点运动及简化Mask不是CFD或实物电润湿动力学模型。

## 3. 算法语义与迁移接口

| 模块 | S3实际语义 | 可直接保留的语义 | 真实输入、差异及验收要求 |
|---|---|---|---|
| G覆盖门 | 目标eta达到阈值、源区eta释放；源准备另用公共P0 | 源/目标分离，eta分母为液滴像素面积 | 同一坐标域的Mask和电极多边形；不能把rho_target替代eta_target |
| C0 | 帧身份、流、任务epoch、严格递增时间、任务施加后可用证据；公共约束不消融 | 旧帧/重复帧不能推进证据；任务切换重建窗口 | SDK帧号、时间质量、任务上下文；仅主机接收顺序不足以证明物理曝光因果 |
| Q | 置信度、面积、显著连通域数量等 | 无效观测独立于真实Deviation | 模拟confidence=1不代表真实置信度可靠；U-Net前景均值尚非校准的检测正确概率 |
| W | 连续帧数、持续时间、最大帧间隔、质心和覆盖率跨度 | 无效/断档/重复帧/任务切换不能拼接证据 | 用实际曝光或明确标记的接收时钟；时间质量和缺失必须保留 |
| S | 候选/源目标区域及目标位置门 | 任务约束、目标空间合法性 | 真实轮廓、局部候选集合和标定；未启用的corridor_width或正向门不视为已验证贡献 |
| K | 原始观测历史的位移速度界、预测残差及断档重建 | 历史一致性检查不读取评分真值 | S3公共原始历史与实物PriorFeatures更新策略不同，需另做兼容验证，不能称逐帧等价 |
| P_B | 共用质量/进展/尝试超时等基础保护，不接收非Arrived五状态作为专属保护触发 | 有限重试、任务超时与停止语义 | raw Q作为公共保护输入，但不是所有Arrived决策前的无条件硬否决，见第4节 |
| P_F | 同一基础保护加五状态Deviation等分支 | 真实偏离与观测未知分离、有界局部恢复 | 实物噪声、轨迹和状态标注未验证；不能将系统保护差异全部归因于S/K |
| ArrivalEvent | 特定run/step/attempt/epoch证据形成、一次消费 | 匹配活动任务、同一步不重复推进 | 保留evidence时钟、causality、事件ID；消费不等于电气成功或实际到达的独立证明 |
| Retry | 当前计划步重新尝试，attempt/epoch变化，不新增计划步 | 通信重发与液滴重试分开计数 | 同目标SET=1不一定产生新的电气边沿；模拟解除停滞的响应不能外推到芯片 |
| Recovery | 切回局部源、源确认后再指向目标；受预算限制 | 不自动引入A*或第三章调度 | 需验证真实源电极对应、释放/保持和重新驱动效果；不保证形变液滴可恢复 |
| 任务状态 | 源准备、运输、恢复、pending、终止；3个固定计划步 | pending期间不重复发新事务，终止类别互斥 | 实物需保留事务ID、ACK结果、停止/释放结果；Unknown不是第六种物理运动状态 |

### 3.1 五状态与Unknown

五种物理状态名称为Stationary、Moving、Partial、Arrived、Deviation。Unknown表示当前观测不足、无效或时序冲突，不应据此生成新的到达证据，也不能将上一帧标签当成当前已确认状态。界面可以显示“上次有效状态”作为带时间戳的历史信息，但其不参与当前稳定窗口计数。S2纯到达门与S3完整控制策略、实物五状态识别器不是同一接口。

### 3.2 最小数据接口

复用已有类型，不在本轮新增运行时实现：

- FrameTiming：SDK帧号、设备ticks、SDK主机原始时间、接收monotonic/perf/UTC、曝光时间及其时钟域、时间质量、队列覆盖数、任务epoch。
- FramePacket：来源ID、帧身份、timestamp_s及来源、原图、FrameTiming。consumer帧号与SDK帧号分别保留。
- VisionResult：与原图同尺寸的二值Mask、质心px、面积px、confidence、处理耗时、检测有效性及错误码。
- StepContext：run/step/attempt/epoch、source/target、phase、施加/软件屏障时间、时钟域、时间质量。
- ArrivalEvent：活动上下文、起止帧、证据区间、确认时间、时钟域、因果质量、唯一ID；Ledger只消费匹配当前运输步的首次有效事件。
- 控制日志：策略/保护版本、request_id、sequence、通信attempt、液滴attempt、request/send/ACK/HV/曝光/推理/决策时间，未观测字段为空而不是估算成实测。

实物接入必须经过独立适配层。禁止直接把simulation秒写入host_monotonic字段，或用模拟Applied填充真实ACK记录。

S3的NormalizedMap为复用共享接口，在内部保留了`*_mm`、`*_mm_s`字段名，但其数值实际为pitch、pitch/s，外发日志必须按pitch解释。这是兼容别名，不是毫米标定；不能仅凭字段名就与实物同名特征合池。

## 4. 四主组与桥接公平性

| 研究组 | 到达输入 | Q/W/S/K目标开关 | 保护 |
|---|---|---|---|
| A_fixed | 施加后1.2 s计时；不生成视觉ArrivalEvent | 视觉到达关闭 | P_B |
| B_single | G+C0单帧 | 全关闭 | P_B |
| BTQ | G+C0+Q+W | Q/W开，S/K关 | P_B |
| F_full | F_arrival到达门 | Q/W/S/K开 | P_F |
| 桥接补充 | BTQ；F_arrival | 各自不变 | BTQ/P_F；F_arrival/P_B |

源码、G3审查及开发manifest显示B_single到达Q关闭，早期报告“G+Q”为文字错误，不是开发数据实际变更。公共raw Q仍送入保护通道；P0与恢复源确认不随目标开关改变。

重要限制：EventController中Arrived处理先于后续质量/进展超时分支。因此“有公共raw Q保护”不等于B_single每次到达确认都被Q硬门过滤。B_single允许高风险单帧确认是冻结对照定义的一部分，本轮不修改其控制优先级。真实安全设计不能只依靠该研究基线；真实研究中需单独声明安全联锁与算法判据的区别，且不能静默改变组别。

S3将原始观察历史计算与S/K目标开关分离。实物PriorFeatures则在Q有效、空间及时序检查通过时更新运动历史。二者均有用途，但误观测后的历史重建行为可能不同；实物方法若宣称与S3相同，必须保存每帧原始特征、门输出和历史更新记录，并用离线同输入反例核对。此项属于实物迁移工作，不是现有S3统计无效的证据。

## 5. Request、Applied、ACK与高压输出的事件定义

| 事件 | 时钟与记录 | 确切含义 | 不支持的推断 |
|---|---|---|---|
| sim_request | simulation时间 | 模拟控制器提出命令 | 不是串口已发送 |
| sim_applied | simulation时间 | 模拟事务延迟结束，World激励目标更新 | 不是固件ACK，也不是实际高压测量 |
| sim_response | simulation时间 | World响应延迟后运动受动作影响 | 不是实测液滴启动延迟 |
| real_request | PC monotonic/perf | 客户端发起事务的observer事件 | 不等同最后一字节写入或硬件动作 |
| real_send | PC时钟 | BEGIN/SET/COMMIT各发送记录及结果 | send成功不等于收到或执行 |
| real_ack_receive | PC时钟 | 匹配sequence的ACK:seq:APPLIED被接收 | 固件报告应用，不是独立电压、波形幅值、刷新完整性或液滴到达证明 |
| real_hv_output | 仪器时钟，经独立对齐 | 测量指定电极实际输出达到预定义电气条件的时间区间 | 缺测时不能由ACK代填 |
| real_visible_arrival | 视频曝光时钟，经对齐 | 独立人工标准下可见到达区间 | 不是World内部位置/速度真值或完整液滴体积到达 |

真实顺序通常期望request→send→固件应用→ACK接收，但实际输出相对ACK的偏移只能测量，不能预设。ACK接收晚于固件内部应用；其时间不能当成准确的物理施加时刻。FrameCausalityGuard在已映射曝光时间晚于ACK屏障时可给出软件`exposure_order_verified`；该标签仍不等于已测实际高压。只有receive晚于ACK时保留`causality_unknown`。

分段延迟分别报告：request→ACK（主机事务延迟）、曝光结束→图像可用、图像可用→推理完成、推理完成→决策、决策→request、ACK→测得HV（有独立计量时）、HV→独立可见运动/到达。不同仪器时钟无可信映射时只报告各域内时长和无法评价项，不相减。

## 6. 空间特征与真实地图的对应边界

### 6.1 已有真实设计与运行模板不是同一文件

冻结S3配置的map_path为空，SimulationMap因此使用`example_420_template_not_measured`示例模板分支；它不是后来提取的FBC6-3 Gerber真实轮廓。核心任务编号可以对应，但不能因此声称正式S3已经使用真实420轮廓或验证外围运输。本轮不更换地图或重跑结果。

真实FBC6-3设计地图为400核心+20外围，共420轮廓；单位mm、名义pitch=3.2 mm，保留外围不规则几何。编号根据已核对的PC布局方向与形状绑定：核心左上1、右上20、左下381、右下400。Gerber轮廓提取不等于网表、电气连通或实物制造尺寸验证，实际地图明确记录未完成这两类验证。

运行用`configs/electrode_map.yaml`仍含模板角点及外围示例结构，不能视为真实配准结果；真实设计JSON不能未经适配直接替换现有ElectrodeMap。AMActuator目前只接受1–400核心目标，通用事务客户端的420范围不表示第二章外围运输已验证。

### 6.2 几何量定义

eta_source=|M∩Ω_source|/|M|；eta_target=|M∩Ω_target|/|M|；rho_target=|M∩Ω_target|/|Ω_target|。当前特征实现采用图像像素栅格面积，透视成像下不是物理mm²面积比。若需物理面积解释，应另行验证平面整流或面积加权计算，并使用新实物研究版本，不追改S3。

观测位置采用二值Mask图像质心，经H变换到设计平面；在一般投影下，“映射图像质心”并不严格等于液滴投影物理面积质心。目标距离、沿源目标方向投影距离、横向偏差均依赖这一观测定义。进展距离有长度单位，进展比例为无量纲，不能混写。

真实距离和速度需绑定H、ROI偏移、图像是否裁切/缩放、去畸变域及电极中心定义。仅接收时钟下的速度应标作接收时间估计，不能声称已验证曝光时刻速度。S3使用pitch和simulation秒，不能只乘3.2就完成实物动力学或阈值标定。

## 7. 独立参考及主要指标对应

| 指标 | S3冻结定义/输入 | 实物对应参考与必要附注 |
|---|---|---|
| planned trials/steps | 全部预声明trial，每条3个计划运输步 | 实物计划清单先登记，源准备失败、未尝试也保留；不能因无预测删行 |
| source_prepared | 公共P0成功；与运输分开 | 记录算法源确认及独立人工源就绪判断，二者不合并；相应分母均给出 |
| transport_complete | 软件流程走完 | 仅执行完毕，不等于真实路径成功 |
| reference-supported path_complete | 端到端公共源准备有独立参考支持，且每计划步Request被当前独立参考支持 | 源区及每步由独立视频参考和连续驻留区间支持；含不确定参考时严格完成不成立，另报告不确定路径；受控运输诊断不冒充源准备成功 |
| premature/unsupported Request | 请求时未被独立参考支持 | 早于人工区间、明确未到达、不可判别分开，不能将不可判别全记为错误 |
| Applied支持 | 独立评价模拟Applied瞬间 | 实物分开评价ACK接收和HV时刻；后到达不追认早先request安全 |
| confirmation delay | 参考区间到确认时刻 | 报告延迟区间及成功条件分母，漏确认不填0；时钟不可靠时不可评价 |
| completion time | 成功时间；失败按24 s计的预算化指标另列 | 按新实物预声明预算计算，不直接沿用24 s；成功条件均值与全计划时间代价分列 |
| Retry/Recovery | 液滴动作次数；不增计划步 | 与同sequence通信重发、ACK超时分别统计，保留实际激励变化是否发生 |
| 保护停止/终止 | 源失败、运输中止、无支持流程完成、参考支持完成互斥 | 保留同一流程类别，另附安全停机、释放失败、硬件错误、视频不可评价标签 |
| Unknown/缺失 | 保留时长、帧数、未尝试和删失 | Unknown不是人工五状态GT；五状态准确率需单独人工状态标注，不能由事件评分代替 |

### 7.1 实物视频参考协议（本次仅规定，尚未采集）

1. 冻结独立于待测算法阈值的人工判定规范：识别目标任务、可见液滴主体与目标关系、可辨静稳及持续可见条件；不直接复制eta阈值或模型预测为GT。
2. 原始视频、source/target/step、ROI和图像域均可追溯。评审界面隐藏算法预测、覆盖率曲线和算法确认提示；允许查看经独立核对的电极位置，不用待测算法输出吸附边界。
3. 两名独立评审记录最后明确未到达与首次明确到达对应的帧曝光区间，并记录后续离开目标的时刻及遮挡。分歧保留后再裁决，报告评审间差异；同视频重复点选不是独立实验。
4. 人工标签使用arrived、not_arrived、uncertain、occluded、right_censored。只有完整可解释观察窗才能标not_arrived；参考缺失保留计划分母。Unknown预测不反向改变人工参考。
5. 同目标Retry在物理驻留未中断时不清空参考；真实Recovery切换激励和离开目标必须分段，不能用旧到达事件无限支持后续请求。现有event_evaluation按步到达区间评分，尚不足以自动完成S3所有“当前驻留段/激励段”审计，后续真实评分适配必须显式加入这些记录。
6. 帧率、曝光区间、滚动快门/SDK语义、掉帧、PTS与曝光映射、主机—设备/仪器同步残差均计入不确定性。低帧率下区间应变宽，不用线性插值创造精确到达时刻。

### 7.2 时间与统计规则

将参考总不确定区间记为[L,U]，事件总时间区间为[c_low,c_high]；端点已经包含曝光、人工和对时误差，避免重复叠加。若c_high<L则确定提前；若c_low>U且整个请求区间位于仍有效的目标支持段，则可判参考支持；相交则时间不确定。零宽区间的边界等号按预注册规则处理。确认延迟区间为[c_low-U,c_high-L]。

现有`dmf/vision/event_evaluation.py`接受单点预测时间和人类参考区间，支持不确定/遮挡/右删失、重复事件和全计划分母。其边界规则为t<L提前、非零区间内含上端点为模糊、t>U为确认；零宽参考允许零延迟。上段双区间和当前驻留评分是**待实现的实物适配协议**，不能冒称当前评分器已全部支持。

独立统计单位：仿真为场景内配对seed/trial；同trial三步、数百帧不是独立重复。真实实验以独立采集/加液/装夹批次为分组，报告芯片、批次、视频、trial、step层级；同轮10段视频不能视作10次独立采集。配对控制比较需预声明随机顺序、阻断/清洗和批次效应；重采样以独立批次或配对trial簇进行，不把帧当n。尚无独立实物批次时仅作Pilot描述，不给出泛化优势结论。
