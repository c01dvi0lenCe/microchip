# 不动电极的 30 秒录像验收

目标是核对**本段录像的 SDK 交付、AVI 保存与主机收帧时间**。不需要液滴动作或电极输出，不验证曝光时间、识别准确率或物理闭环。检查程序只读本地文件，不会连接相机、串口或改写旧录像。

## 更新相机电脑

如使用本次增量包，应已有同版日常上位机（含多组定时开环与四步循环）。先关闭上位机，备份原项目；若相机电脑有独立修改，先合并，不要直接覆盖。将包内文件按原目录结构放在 `main.py` 所在项目下，再按原方式启动。包不替换相机配置、SDK、模型或录像，不需重新烧录 STM32。它不是给空目录使用的独立安装包。

本次还改了开环启动：**预检只显示，开始才执行**。例如路线 190→191→192，191 和远端 350 已亮：只发 191 关闭，等到对应 APPLIED，才另发 190 开启。350 不关。若路径外的已亮电极与路径确实冲突，提示并拒绝启动，不替操作者关闭它。本次录像基线不需要试这个动作。

## 录一段独立视频

1. 在相机电脑上启动正常上位机，保持 STM32 串口断开，不启动任何定时任务，不操作电极或外部电源。仅通过 PC 的 USB3/SDK 打开工业相机预览，等到画面稳定。保持原采集参数、曝光和图像尺寸。
2. 要单独测录像瓶颈，取消勾选 **录像联动检测**，并确认独立检测也已停止。如果还想观察平常的推理负载，另录一段标明“联动开启”的对照，不混用两段结果。
3. 点击**开始录像**。看到开始成功和保存路径后再计时，持续约 **32 秒**，点击**停止录像**，等待保存结束后再关闭程序。检查按首末**已保存帧**的收帧时钟衡量 30 秒，不用按钮计时或 AVI 播放时长代替。
4. 在日志指示的目录中保留同一文件名开头的所有文件；特别是 `.avi`、`.timestamps.csv`、`.recording.json`、`.capture.csv` 和 `.gaps.csv`。不要只拷贝 AVI。零缺口时，新格式仍有带表头的 `.gaps.csv`。

## 检查命令

在上位机项目目录，用能运行上位机的 Python，替换引号中的路径：

```powershell
python -m scripts.check_recording_continuity "D:\录像\camera_实际文件名.avi"
$LASTEXITCODE
```

会逐帧解码，打印 JSON，不写报告文件。默认要求首末保存帧相隔至少 30 秒。若只想诊断短片，可加 `--min-seconds 0`；这种结果不能作为 30 秒验收。

| 看哪里 | 怎么读 |
| --- | --- |
| `outcome` / 退出码 | `pass` / 0：本段通过指定时长的严格检查。`fail` / 1：查看 `integrity_errors`（缺文件、文件不完整、帧身份或计数不一致）和 `acceptance_failures`（时长不足、掉帧、时间窗中断等）。`unverified` / 2：旧格式可读，但无独立 SDK 交付记录，不能判定上游或本地掉帧。 |
| `counts`、`capture.frames`、`local_drops_by_reason` | AVI 实解码帧数、AVI 声明帧数、编码/时间表清单、时间表行数应一致。另按**帧号与同一主机收帧时刻**核对「收到 = 已存 + 本地未写」，不只比数量。 |
| `nominal_playback_fps`、`capture.actual_fps`、`saved.actual_fps` | 分别是设置的播放帧率、实际交付帧率、实际保存帧率。后两者按 `(帧数−1) / 首末收帧时间差`。AVI 播放流畅不等于实际采集连续。 |
| `capture` 与 `saved` 的帧号指标 | `missing_between_ids` 为相邻可判定帧号之间的缺号总数；`missing_range_length_histogram` 给出“每次少几帧 → 出现几次”；`longest_consecutive_sdk_run` 是最长连续递增帧数。重复、倒序、未知号单列；倒序或未知附近不臆测缺号数量。前 20 个事件在 `first_id_events`；新格式完整交付/本地事件在 `.gaps.csv`。 |
| `saved.window_eligible_ends`、`saved.max_receive_gap_s` | 前者数的是**可结束一个合格窗口的帧数**（可重叠，不是到达次数）。窗口要求 SDK 帧号连续、至少 5 帧、首末至少 0.25 秒、每个相邻间隔不超过 0.18 秒。高帧率时可能需要超过 5 帧。后者是整段最大相邻收帧间隔；即使存在合格窗口，整段有超限间隔仍不通过严格检查。 |

一个判读例子：SDK 交付 10、11、14、15，而 AVI 保存 10、14、15。SDK **交付边界**已缺 12、13；11 才是本地未写帧，具体原因看 `local_recording`。仅从 AVI 看到三个缺号，不能说相机丢了三帧。即使确认 SDK 交付时有缺口，也不能仅凭此断定是传感器、USB 或驱动的故障。预览替换与录制是不同路径，预览计数不计入本地录像损失。

整段无超限间隔是**本次不动电极基线**的严格门槛；超过 0.18 秒只是跨该处的窗失效，不等于发生 SDK 缺帧或整段录像不能用，其他时段的合格窗口仍分别计数。

严格通过只表示这一段从首帧至末帧的可核对范围内，文件完整、交付帧号连续、没有本地录像丢帧，且满足上述时序条件。不代表录制边界外没有丢帧，更不代表液滴到达。保留失败片段及全部侧车，先对照故障边界，不补帧或放宽识别时间窗。
