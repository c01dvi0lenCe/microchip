# 真实实验操控界面与独立仿真入口

## 本次用户确认的分工

日常上位机只用于真实实验操控，仿真由研究工作流独立运行。所有定时开环放在“手动电极”页，依赖视觉反馈的任务放在“自动化路径规划”页。当前不启动实际AM、不连接相机、不修改STM32/300Hz扫描或串口事务协议，不更改冻结S1/S2/S3结果。

## 启动及兼容边界

- 日常入口：`python main.py`。明确使用operator_only=True，固定实物语义、默认串口断开。没有自动连接、自动点亮或自动打开相机。
- 研究仿真：`python run_planning_simulator.py`，由研究工作流使用。明确使用simulation_only=True，正常入口下不能切换真实串口；原有各章CLI及冻结结果保留。
- 两入口共用`dmf.layout`和`CanvasControllerMixin`，420编号、核心及外围位置、角部轮廓、连接段与邻接关系不复制、不重新编号。匹配视口下的几何回归逐一核对。
- 旧`STM32MatrixController(root)`构造器继续为研究回归保留兼容行为，日常main明确选择实物profile；研究源码没有物理搬出仓库，更没有删除冻结文件。

## 手动电极页

1. “电极开关”用途：按原手动方式操作，16格故障/保护提醒继续显示，手动许可不变。
2. “任务选点”用途：只编辑路径，不发送电极指令。普通移动分别设置起点、终点；多组四宫格逐组设置起点、有序四点和终点，起终点仍须在2×2内。两处“起点/四点/终点”选择器都会自动转入任务选点；直接点亮前需明确切回“电极开关”。
3. 开环预检、停留/圈数、开始、单步、暂停/继续和停止均在本页。每次运行继续使用既有APPLIED同步步进，已完成组及额外保持点不被其他组关闭。
4. 预检仍检查故障区、同格/对向/邻接吸引风险及保持点冲突。未完成组会列明缺项并自动选中首个未完成组，不猜测电极。例如“G1未设置起点；G2未设置终点、四点（已选2/4）”。
5. 起点/终点选项不会因为完成四点而被隐式填写。只有全部配置和预检通过才允许执行；请求与APPLIED仍不是物理到达。
