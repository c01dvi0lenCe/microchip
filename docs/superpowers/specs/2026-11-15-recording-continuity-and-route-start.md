# 上位机录像连续性与开环启动准备

## 相机

- MVS 采集按 SDK 顺序取原始帧；预览/显示保留最新一帧，旧预览可被覆盖。录像不得从显示或推理队列取样。普通预览不能积压过时画面。
- 录像期间复制已取得的原始像素及同帧元数据，尽早归还 SDK 缓冲。按先后次序交给独立的录像写入执行单元；不得把指向已释放缓冲区的指针放入队列。录像队列受内存限制，不能无界堆积，也不能无记录地覆盖旧帧。工作线程构造/提交持有原始像素的编码输入；停录等待待写帧与日志收敛后再关闭编码器。
- 以 SDK 帧号和高精度主机收帧时钟记录跳号前后、缺失范围及数量；区别已经取到但本机没有写入的帧、SDK交付时已经存在的缺口、重复/倒序和仅预览被替换。未知原因不要归为相机或USB故障。录制文件写坏或计数不符标为不完整，即使关闭日志成功也不能冒充连续。保持现有 AVI、时间表和电极关联兼容，不重写以往录像；不补帧、不改冻结识别窗，不自动调整相机曝光和采集帧率。
- 以仿真 SDK/内存测试验证所有权、慢写、溢出、停止、编码失败及缺口对账；实际相机上做一次不动电极的 30 秒录像，检查收帧/编码/时间表数量、SDK连续帧、缺失分布、成功形成的时间窗口。软件测试不承诺硬件零丢帧。

## 开环任务

- 预检无电气副作用。任务范围是所有组实际路径上全部电极，含起点、中间点、终点。与当前已确认 ON 集合相交的是启动待关集合，不算外部保持。其余已确认 ON 作为外部保持，仍受原冲突/故障检查；确有冲突时报出位置，不替用户清除。
- 启动重新检查已确认状态及在途事务。若待关集合非空，先以现有原子增量事务仅关闭这些电极，收到相同序号 APPLIED 后才单独提交原首步。若为空则直接开始；不发送 ALL_OFF。不把清理记作运输步，不用清理 ACK 计停留时间。停止/关闭中、失败、状态不明不能再开启首步；在途时保持唯一事务所有权。
- 不改四步循环的顺序、圈数、停留、路径与运行中的任务外手动开关规则。不改 STM32，不连接相机、串口或高压进行本机软件测试。
