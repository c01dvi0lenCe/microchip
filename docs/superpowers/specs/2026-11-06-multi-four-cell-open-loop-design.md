# 多组四宫格单液滴同步移动与故障极性修订

## 已确认需求

- 不是混合，不做液滴汇合、分裂或颜色混合评价。每组对应一个已有液滴，用户可以添加多组。
- 与自动化路径规划一样在画布选点，不只输入单个左上角编号。
- 用户逐组设置起点、四宫格四个电极及终点；多组同时执行，统一原子事务与步进时钟，检查路径/保持电极冲突。
- 相机可以预览和录像，识别结果暂不参与执行。STM32继续只执行原协议，300Hz扫描不变。

## 已完成的故障规则更正

用户补充的实际故障分类：持续导通90、337、393；无法导通399、400。仅持续导通类扩展上下左右，故红色共16格：

70、89、90、91、110、317、336、337、338、357、373、392、393、394、399、400。

379、380、398不再标红。界面悬停区分故障类型与邻接提醒，手动点亮能力按先前明确选择保留。关闭命令、软件显示0、ACK:ALL_OFF不能证明已损坏器件实际隔离；不能把红色提醒当成修复措施。

## 推荐结构与取舍

采用独立的多组定时路径执行器，复用原路径编辑交互、现有冲突检查和事务客户端。各组不分别开线程发串口；只用一份批量事务申请完整的下一步电极状态。

不采用多个独立定时器分别控制一滴，避免同一时刻交叉覆盖电极状态；不解除旧仿真auto_loop限制，不读取模拟液滴或模拟相机；不把多组自动任务下放固件。

## 画布与任务数据

自动化规划页增加明确的“实物定时开环／四宫格单滴移动”入口，旧仿真和视觉闭环入口保留。

任务列表每行一组：组ID、起点、按顺序选四个电极、终点、路径预览和校验状态。支持添加/选择/删除/清空，点击画布更新当前组，图上显示对应组标签和方向。

首版四宫格必须为核心1–400中的一个实际2×2块，四个点互异、按点击顺序逐点四邻接且首尾相邻。起点和终点必须属于该四宫格；如果用户想从外部源点先运输到四宫格再运输到外部终点，应另行纳入后续路径任务，不在当前版本中静默生成额外远程路径。

共同设置单步停留与圈数。按用户所选四点顺序，从起点开始绕行指定完整圈数；再沿同方向的最短前缀到所选终点并保持。预览明确显示额外末端停靠步，终点等于起点时不加步。首版不增加各组独立时钟或私自优化方向。

## 同步执行与保持

1. 启动前冻结各组路径、圈数、停留、额外保持电极。运行中编辑不改变本次任务，只有停止后才能重新生成。
2. 每一全局步，各个未完成组最多前进一个相邻电极；已完成组保持终点。生成下一完整活动集合，包含所有组当前位置和明确的额外保持集合。
3. 已有不属于任务的活动电极不静默关闭：启动前显式列为额外保持集合，纳入冲突预检；不合格时返回用户调整。
4. 一份BEGIN/SET/COMMIT仅提交变化量，全部组共用一个APPLIED确认。ACK未完成不更新任何组的执行索引；最多2次同sequence通信重试，失败进入停止/状态不确定。
5. 收到APPLIED确认返回后等待共同停留，或按单步按钮请求下一同步步。没有视觉ArrivalEvent，也不以电极序列完成判定液滴真的到达。
6. 普通停止保留最后确认状态；在途停止先取消未来请求，待当前ACK/失败结果收敛。全部关闭与窗口关闭释放按已有客户端串行规则处理，禁止释放后迟到开启。
7. 与手动切换、旧自动任务、单组定时器及第二章experiment互斥；相机预览录像不占用电极控制器，不把拍摄帧用于决定切换。

## 启动预检

必须使用既有规则检查同格、对向交换、相邻/斜邻吸引风险、已完成滴及额外保持电极占用、轨迹/身份连续性。冲突时拒绝启动并指出组ID/全局步/电极，不用部分组先运行的方式兜底，不更改第三章规划算法。

考虑持续导通故障，推荐本次新的同步自动入口默认拒绝经过16格故障/保护区的路径与保持点，而不是仅弹窗后当成安全。手动测试仍允许点亮；这是自动执行单独的准入规则，需用户批准本设计后实施，不静默改变旧planner/障碍集合。

软件预检不能保证持续导通像素被真正断开；正式实物自动运行前仍须完成独立隔离/电气状态检查及硬件急停确认。
