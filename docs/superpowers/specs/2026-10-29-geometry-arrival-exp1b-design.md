# 实验一B：异常工况下到达识别与约束消融设计

日期：2026-10-29。状态：用户已确认研究方向；本文新增的具体机制工况和评分细节待审。未编写新算法或运行新trial。依据为已封存SDF工作模型及用户本轮审查意见。

## 1. 科学问题与方案取舍

核心问题是在相同模拟Mask、时钟及任务下，Q/W/S/K是否在共同G门之外产生可解释的错误拒绝、正确确认损失和延迟代价。M3可以与M2相同，也可以表现更差；不以M3必须胜出为验收条件。

三种推进方案：

1. **推荐：共同缓存的固定机制集先行**。先核实异常实际发生、约束组合正交、独立参考及评分正确，再冻结小规模随机探索。能定位没有差异的原因，减少无效重复。
2. 直接每类20seed。代码量和统计结果较多，但若S/K根本不触发，增加次数不能填补机制证据；当前不采用。
3. 直接进入多电极闭环。会混合到达门与控制反馈、重试/恢复的影响；留给实验二，不在本阶段执行。

不继续调整形态、引入CFD、牛奶/血浆、新分割网络或多液滴规划。

## 2. 数据流与隔离

真实设计地图 + 封存SDF形态库 → 独立运动/异常注入 → 内部轨迹与模拟相机 → 持久化共同Mask缓存 → 6个到达门 → 独立评分。

- 仍仅190→191，一次0.50 s请求，0.54 s模拟Applied，0.72 s响应；识别事件只旁路记录，不反作用当前轨迹。
- 内部位置、速度、运动阶段及独立参考独立保存；算法只接收Mask、帧身份、曝光/可用/处理时间、当前任务、地图。
- 生成器可用内部运动阶段定义异常，但异常标签、阶段和参考不传给算法。
- 每缓存所有方法读取同一有序递交记录，记录cache hash；同一基础运动的不同观测扰动不算独立World重复。
- 不修改`shape_sequence.py`、`sdf_trial.py`、`shadow.py`或现有正式算法。独立命名空间拟为`dmf/chapter2_geometry_sim/exp1b/`，只调用封存形态和公共EvidenceWindow/ArrivalEvent。

## 4. 拟议第一批固定机制工况（16缓存，不作性能统计）

以下数值是预声明软件假设，**不是实测误差分布**。固定夹具没有“20次重复”的含义。1px指虚拟40px/mm栅格，即0.025 mm；不是原视频像素到毫米标定。

| ID | 组别/工况 | 固定输入改变 | 机制目的与负对照 |
|---|---|---|---|
| A0 | 正常 | 重放当前6 s缓存；新10 s随访版本只增加已到达静止尾段 | 先逐项复现4.40/4.65/4.65 s；不因新增代码改变原事件 |
| B1 | 缓慢 | 独立运动峰值0.7 mm/s，其他参数不变 | 参考由新内部轨迹重算；不沿用4.72 s |
| B2 | 短暂停滞 | 内部进展0.55时暂停运动时钟1.0 s后继续 | 暂停期间不拼造目标参考，恢复仍用原SDF进展 |
| B3 | 最终卡滞 | 内部进展0.55后永久停止 | 无参考到达，不能指定虚假的参考时刻 |
| C1 | 小抖动 | 4.20—4.50 s观测中心逐帧横向±1px交替 | 小幅负对照，不要求任何门额外拒绝 |
| C2 | 位置偏移 | 4.20—4.50 s观测中心横向固定8px | 观察G/S重叠；不得为获得S差异扩大幅度 |
| C3 | 局部缺失 | 同窗从运动方向后侧裁去Mask外接框长度的20% | 仅改观测不改World；记录实际面积/连通性/G变化 |
| C4 | 破碎观测 | 同窗删除穿过质心的一条2px宽横向带 | Q能否拒绝取决于实际连通域，不能直接写Q=false |
| C5 | 短暂误检 | 2.00 s一帧替换为固定目标紧凑模板 | synthetic stress；共同W能否消除瞬态事件 |
| C6 | 持续误检 | 2.00—2.30 s七帧使用相同目标紧凑模板 | synthetic stress；检查K首跳拒绝后适应及6帧余窗，保留可能失败 |
| D1 | 单帧丢失 | 不递交曝光4.40 s一帧，帧号不重编号 | 新旧数据身份完整，W重建；不补造Mask |
| D2 | 连续丢失 | 不递交4.30—4.50 s五帧 | 触发时间断档并重建历史/窗口 |
| D3 | 重复 | 曝光4.40 s的原帧原时间原ID再次递交一次 | C0拒绝重复，无新物理样本 |
| D4 | 乱序延迟 | 4.40 s原帧额外延迟0.30 s递交，其他帧正常 | 到达顺序与曝光顺序分开；延迟本身不篡改曝光时间 |
| D5 | 旧任务帧 | 曝光4.40 s递交有效Mask但捕获context为旧epoch | C0拒绝；不把图像内容正确当成任务因果有效 |
| D6 | 合法新帧突跳 | 4.40 s观测整体横移1.20 mm，帧/时间/context合法，下一帧恢复 | synthetic stress；24 mm/s量级能检验现有K边界，但不能外推真实发生率 |

为什么不保证每个模块都出现统计收益：大幅位移可能已被G拒绝，破碎Mask可能同时改变G/Q/S；这些重叠是要报告的结果。另用手算gate夹具检验开关能触发，但不将其计入以上缓存或性能统计。S若在合理形态/偏移范围内总被G包含，报告该冗余，不增加不合理细尾来制造优势。

近到达观测误差放在固定减速末段4.20—4.50 s，避免全部异常发生在G本就不满足的早期而无法检查证据重建；伪目标误检则放在明确的迁移中段2.00 s。这是开发机制时段选择，不是异常发生概率模型。各门共用时段，尚不据此估计随机性能或真实发生率。

共用10 s观察终点以覆盖0.7 mm/s正常慢速恢复；当前6 s原例不改，新A0尾段以独立版本记录。所有方法同一终点，延迟帧未在终点前可用则保留删失。B1预计时长只用于选择足够随访，不当作实际结果。

## 5. 评分冻结草案

独立参考沿用内部距离≤0.288 mm、速度≤0.192 mm/s、连续驻留≥0.15 s，不使用覆盖门。保存每个合格驻留起止区间及驻留完成时刻；离开目标则结束支持，不让旧参考支持后续请求。

主比较使用算法**处理决策时间**，同时保存证据首末曝光、图像可用、处理、参考起始/完成各时间；不能拿曝光时间当控制决策时间。

- planned steps：每缓存1步；所有6方法保持完整分母，包括无有效帧、无事件及执行错误。
- reference arrivals：观察终点内完成驻留的参考事件数；卡滞无到达记0，不补参考时刻。
- supported confirmation：决策位于该参考驻留完成后且尚未离开目标的区间。
- premature confirmation：本窗内后来存在参考到达，但方法在其驻留完成前消费事件。另标“参考驻留开始前”或“驻留建立中”，不直接写成实际电极损害。
- unsupported confirmation：当前决策没有可支持区间，且不属于可确定的提前事件；无到达卡滞、目标离开后错误确认等单列。
- missed reference：参考存在但没有匹配的受支持事件；与先前错误确认标志可以并存，不强迫这些不同分母的指标相加等于100%。
- latency：受支持确认的决策时间减相应参考驻留完成时间；同时报告支持数/参考数，不能只对成功样本报告延迟而隐藏失败。
- signed deviation：对于可匹配的首参考报告带符号时差，负值不是“负延迟”。无参考值为NA。
- censoring：到终点仍缺随访、延迟帧未可用、参考建立未完成各自标记；没有参考不自动等于算法漏检。
- 当前无五状态分类，不生成虚假的Unknown分类准确率；无效/无观测以观测状态字段保留。

## 6. 逐门可归因日志

每递交记录保存C0及原因、原始G/Q/S/K、原始历史位置/曝光/速度、每组合的W样本ID/计数/跨度/清空原因、事件是否首次消费。原始特征在不同方法中逐项一致；算法不得读异常类型或参考标签。

至少输出：

1. 各原始门失败数；
2. 在C0/G/Q候选中S/K新增拒绝数；
3. G/Q/S/K拒绝交叉表；
4. 新增拒绝是否实际改变最终事件、是否阻止错误或损失正确确认；
5. 同一World不同观测缓存与不同运动World的层级，不把逐帧当独立试次。

## 7. 拟新增文件与接口

不实施对旧模块的原地重构。以下是待审接口草案，不是已完成能力：

- `exp1b/spec.py`：不可变GateSpec、CaseSpec、终点和单位校验；方法清单由布尔组合定义。
- `exp1b/gates.py`：共同RawObservationAssessment、独立GateRunner与一次性ArrivalEvent；所有组合读取同一原始历史快照。
- `exp1b/generate.py`：复用SDF库/地图/最小跃度，独立生成运动或Mask/交付时序异常；保存每个实际Mask及异常清单。
- `exp1b/evaluate.py`：只接收保存后的内部参考区间与预测事件，返回完整计划步表及匹配原因。
- `exp1b/audit.py`：不调用识别器复算覆盖、参考、事件时间和各分母；验证封存hash。
- `tests/test_geometry_exp1b.py`：正常兼容、6组合正交、旧/重复/乱序帧、无参考、驻留未满、离开目标、晚到/删失、K适应与G/S重叠。
- 独立执行/绘图/报告入口：在方案通过后由实施计划确定；不复用会覆盖旧输出的脚本。

G0：核对本文工况/时间/评分，用户确认后形成版本化配置；不使用试验结果倒推阈值。

G1：先RED→GREEN实现手算测试与正常兼容，当前缓存必须复现三时刻；事件一次消费，Raw K历史对6方法完全一致；C0无法通过消融关闭。

G2：运行16固定机制缓存，检查异常实际幅度、面积/连通、门触发与重叠；任何无法按声明生成的case记失败，不静默替换。每缓存6方法，共96方法记录，但不是96独立试次，不报告总体准确率或95%性能区间。

G3：交付机制核查/负面结果/原始逐帧与逐事件/来源hash及Chat审查PDF。只有确认机制与评分成立后，提出随机分布、开发seed与20配对seed探索方案；本设计不自动批准批量运行。
