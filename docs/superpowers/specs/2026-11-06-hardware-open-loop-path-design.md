# 实物定时开环路径执行：相机预览独立、暂不接视觉判定

> 后续用户已明确“多组四宫格单液滴同步移动”，不是混合。最新设计见 `2026-11-06-multi-four-cell-open-loop-design.md`；本文件单组首版范围与红色19格为历史提案，不作为最新执行要求。当前红色已修订为16格。

## 本轮方向

用户确认先接入开环路径规划，视觉暂不接入。相机仍可使用现有MVS入口预览/录像；画面、Mask、检测位置不参与本模式的电极推进。不开COM端口、不启动高压、不自动操作相机设备，不修改STM32源码或第一章AM刷新。

## 实现方案

优先方案为独立的实物路径执行器，复用现有规划结果及APPLIED定时事务基础设施，不解除旧仿真控制器的运行限制。旧闭环控制器仍可运行仿真，新执行器不调用模拟液滴更新或模拟相机。

其他方案：直接放开旧auto_loop会把模拟状态带入实物控制，不采用；把规划与循环下放STM32违反现有控制归属，不采用。

## 首版范围（待最后确认）

- 单液滴核心区移动，以及单液滴已规划的循环路径；核心1–400四邻接逐步校验。
- 混合可继续使用已有独立定时四宫格；旧两滴自动汇合、分裂、多滴规划只预览，不在本次新入口执行。
- 允许相机预览和录像同时进行。相机断开/停止只影响预览录像，不构成到达事件；串口断开则终止后续路径命令并标记电极状态未知。
- 模式名称明确为“实物定时开环”，不标识为视觉闭环成功。

## 执行语义

1. 用户规划后检查完整电极序列，启动时冻结路径、停留时间与循环次数。运行中修改规划不得改变本次序列。
2. 只有串口已连接、状态明确、没有未完成事务或其他控制任务时才能启动。初始仅允许源电极活动或全关，不静默关闭其他持有液滴的电极。
3. 每步一份BEGIN/SET/COMMIT事务，等待APPLIED；沿用现有同sequence最多2次通信重试。ACK失败不推进；保持软件状态未知并提供释放入口。
4. 定时模式在APPLIED确认返回后保持至少设定停留时间，再请求下一步。停留可调，不等于已标定的液滴运输时间或精确更新周期。
5. 手动单步仅在上一事务完成后允许；不提供自动推断液滴位置的回退。正常停止/结束保留末电极；全部关闭沿用ALL_OFF。在途事务与释放串行化，禁止释放后的迟到开启。
6. 红色提醒仍然允许手动点亮。自动开环启动前如路径经过红色19格，必须列出并由用户显式确认，不静默当成安全路径；不修改原规划算法或障碍语义。
7. 手动、定时四宫格、旧仿真自动任务与第二章experiment互斥。停止/复位/失联/模式切换/窗口关闭均取消后续执行。

## 日志与完成含义

保存规划序列、每步request、真实APPLIED软件接收记录、计时起点、停止/失败原因；相机已有录制日志继续保存。不把电极序列执行完毕写成液滴运输成功，不伪造视觉ArrivalEvent。

## 测试验收

先以纯状态机和内存串口验证：四邻接、路径冻结、单事务pending、APPLIED前不可推进、单步/停留、红区确认、任务互斥、在途停止/释放、失败/断开、录像并行以及没有调用模拟相机/液滴或真实识别。再运行局部/全量/软件控制链。实物连线、固件烧录版本及硬件安全验证由后续单独流程执行，本轮软件通过不等于实物运输已验证。

本设计不新增真实视觉模型部署、配准、训练或实物实验，不Commit/Push。首版执行范围与书面设计待用户最终确认后实施。
