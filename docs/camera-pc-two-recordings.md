# 相机电脑操作卡：更新、加载模型、录两段、交回数据

更新日期：2026-11-18。给操作者和相机电脑上的 Chat 共用。

**本次只做“你开环操作，系统检测记录”。不启用视觉自动切换，不改 STM32，不需重新烧录。第一段完全不接串口、不动电极。第二段的实物操作与安全检查由操作者负责。**

## 1. 更新代码

先关闭上位机。在含 `main.py` 的项目文件夹打开 PowerShell：

```powershell
git status -sb
git branch --show-current
```

分支是 `codex/whole-chip-realtime-vision`，且没有待保留的本地代码改动时：

```powershell
git pull --ff-only
git log -1 --oneline
```

若在其他分支、有本地改动，或更新报冲突：**不要强制覆盖**。交给这台电脑的 Chat 检查，或另找空目录克隆：

```powershell
git clone --single-branch --branch codex/whole-chip-realtime-vision https://github.com/c01dvi0lenCe/microchip.git
cd microchip
```

保留原项目中的相机本地配置和模型；不要复制旧源码覆盖新版。实现版本至少应包含 `1ab55f1`，这份操作卡是后续文档更新。

## 2. 安装、加载模型

1. 双击 `setup_vision_env.cmd`，等提示依赖安装成功。已有环境也执行一次，以核对版本；需要 64 位 Python 3.14。
2. 下载 [G4 模型 ZIP](https://github.com/c01dvi0lenCe/microchip/releases/download/g4-unet-inference-v1/g4_unet_inference_v1.zip)，按[快速部署的第 2、3 节](camera-pc-quickstart.md)校验、解压和做一次离线推理。已有同一模型且校验通过，不必重下。
3. 最终目录必须是下面这样，不能多套一层文件夹：

```text
上位机项目/
  main.py
  start_vision_gui.cmd
  models/g4_unet/
    manifest.json
    unet_state.pt
```

4. 沿用本机已能取图的 MVS 驱动及 `configs/camera_mvs.local.yaml`。若没有，按[相机接入清单](target-computer-camera-integration-checklist.md)配置，不能把开发机 SDK 路径照搬过去。
5. 双击 `start_vision_gui.cmd`。在“模型包”中选择 **`g4_unet` 文件夹**，不是选择 `.pt` 文件。离线自检失败先排查，不能把原图预览正常当作模型已加载。

## 3. A 段：只录像，不检测，不操作电极

1. STM32 串口保持断开，不启动任何开环任务。点击 **开启预览**，等完整图像稳定。
2. 取消 **录像联动检测**；如果独立检测正在运行，点 **停止检测**。
3. 保持原曝光、增益、分辨率和采集帧率，不在中途改设置。点击 **开始录像**。
4. 看到日志“开始录像”后再计时，录约 **32 秒**，点 **停止录像**。
5. 等日志提示录像已保存。记下保存路径，暂时不要关闭程序。录像保存目录以实际日志为准，不假定与代码在同一文件夹。

让本机 Chat 运行以下只读核对。把引号内换成这段 AVI 的实际完整路径：

```powershell
.\.venv-vision\Scripts\python.exe -m scripts.check_recording_continuity "D:\实际目录\camera_实际文件名.avi"
```

要求 `outcome=pass` 后再进入 B 段。若是 `fail` 或 `unverified`，保留整段原文件和完整输出，先发回排查，不反复改曝光/帧率、删掉失败片段或补帧。此检查衡量首末保存帧的时间，不用播放器时长代替。

## 4. B 段：一滴、一次开环移动，同时检测记录

前提：A 段通过，操作者已完成日常实物安全检查；先不做多组循环。

1. 保持与 A 段相同的相机装夹、分辨率、曝光和增益。准备一滴当前 G4 适用的深色液滴和一条明确的相邻电极路径；可用 190→191，但须以本次实际位置和可用电极为准，避开故障区。记录实际起终点，不为符合示例强行换位置。
2. 检测模式选 **双层优先**。检测尚未启动时，点 **添加观察区**，在相机画面拖框：包含源电极、目标电极、液滴完整运动范围和周围余量。不是只框住液滴此刻的黑色部分。第一次只加一个观察区；无合格配准时不要载入不明旧矩阵。
3. 勾选 **录像联动检测**，点 **开始录像**。它会自动准备模型和检测，不必再抢点“启动检测”。等日志出现“开始录像”，并确认观察区有实际 Mask/叠加结果。若提示“检测未就绪，仍保留原始录像”，该段不是成功的检测实验，先停止并保留错误记录。
4. 先保留约 3 秒静止画面，再由你在“手动电极”页按熟悉的开环方式执行一次迁移。若用“定时开环”，先 **预检**，再 **开始开环**；人工单步模式需由你按 **单步** 推进。视觉不会代替你推进。沿用已试过的停留设置，不为赶进度缩短。
5. 液滴移动结束后再保留约 5 秒画面，并让整段从录像成功开始算达到约 32 秒。任务若仍在运行，先按任务的 **停止** 防止继续循环，再点 **停止录像**。
6. 等待“录像已保存”和“录像及检测索引已保存”，检测保存结束后再关闭相机/程序。**停止录像不会停止开环，也不会关闭电极。** 电极/电源结束状态按你的实物安全流程处理。
7. 拍一张界面截图：能看到观察区、Mask/叠加和检测状态。如果看不到结果、模型判断异常或液滴没到，也保留，不重命名成“成功”。

“添加观察区”只定义像素检测范围，不等于完成420电极配准或确认目标身份。本段不生成已验收的 M2/M3 到达结论，后续还需配准、同滴身份和独立视频参考核对。

## 5. 哪些文件一起给我

**最省事：按下面三处复制完整内容，再压成一个 ZIP。不要移动、改名或重新编码原视频；数据发给研究工作区/本对话，不上传公开 GitHub。**

| 内容 | 到哪里取 | 怎么取 |
| --- | --- | --- |
| A、B 两段录像及同名记录 | 上位机日志中的录像保存目录 | 每段同一文件名前缀的全部文件一起复制，含下表列出的 CSV/JSON |
| B 段实际检测结果 | 打开 B 的 `.vision-session.json`，找到 `detection_directory` | **整个文件夹**复制。默认在项目 `results/realtime_vision/<会话>/`，不要只发 session JSON |
| B 段开环任务日志 | 项目 `results/hardware_open_loop/<对应会话>/` | 若用定时开环，整个对应文件夹复制；只手动点亮时可能没有此目录，注明“纯手动” |

每段录像的同名文件：

- `camera_….avi`：原始录像；
- `camera_….timestamps.csv`：成功写入的逐帧时间；
- `camera_….capture.csv`、`camera_….gaps.csv`：SDK实收及缺口/未写记录；
- `camera_….recording.json`：录像封存与连续性摘要；
- `camera_….electrodes.csv`、`camera_….frame_electrodes.csv`：电极事件及按主机时钟关联；A 段没有动作或状态未知是正常情况；
- B 段额外有 `camera_….vision-session.json`；A 未开检测时没有它是正常的。

检测文件夹需保留 `manifest.json`、`regions.csv`、`events.csv`、实际 `masks/` 和其他已有文件。若用“完整同帧”模式则是 `frames.csv`、`components.csv` 等，也整包保留。检测只保存实际处理的帧，不要求 Mask 数量等于录像帧数。

建议整理成：

```text
相机验收_日期/
  A_纯录像/              # AVI + 同名前缀的全部CSV/JSON
  B_开环加检测/          # AVI + 同名前缀的全部CSV/JSON
  B_检测结果/原会话名/   # detection_directory的完整副本
  B_开环日志/原会话名/   # 使用定时开环才有
  说明.txt
  界面与相机设置截图/
```

`说明.txt` 写：两段原文件名、`git rev-parse HEAD`、GPU及模型后端（cuda/cpu）、模型版本/摘要、液体与实际起终点、定时或纯手动、停留时间、采集分辨率/帧率/曝光/增益、是否自动曝光、实际观察到的异常。已有设置截图可以代替抄数值；不清楚写“未记录”。附 A 段核对输出、安装/自检错误（如有）。

**不用给：**整个虚拟环境、MVS安装包、旧录像、再次复制的权重。不要只给屏幕录制或只给 Mask；那样无法检查原始取帧与同帧关系。若失败导致某个文件未生成，写明缺失，不补造。
