# S3事件驱动闭环控制仿真研究方案（待实施）

日期：2026-10-26。状态：仅研究方案，0新trial、0新预测、0新评分。对应论文2.4.3、2.5.4。限定为简化二维点运动、模拟Mask和pitch单位，不是CFD、真实电润湿或实物闭环验证。

## 1. 科学问题与比较层次

在共同源准备、运动模型、外部扰动、动作延迟、控制预算及独立评分参考下，不同运输策略能否改善单液滴路径完成性、安全性与执行效率？

拆为两个问题，不用一个策略差值同时回答：

1. **到达门增量**：固定相同保护策略时，BTQ与F_arrival的S/K差异是否改变闭环错误更新和参考支持的路径完成？
2. **完整策略作用**：当五状态驱动的有界Retry/Recovery参与时，A/B/BTQ/F策略包的安全、完成和运行代价有何差别？其差异不能全部归因于S/K。

S2只评价外部给定任务下的同输入事件；S3的动作会反作用于世界。共享的是外生随机条件，不是动作分叉后的Mask或内部轨迹。历史v1 A/B/C、v2 E0–E3和正式S2各自封存，不按方法名或seed直接合池。

## 3. 主对照与保护桥接

先定义两种研究保护策略，但共享同一原始观测管线和公共底线：

- **P_B（共同基础保护）**：原始Q/C0、无观测/无进展/最长尝试监控、有限Retry、重试耗尽后的局部Recovery、硬预算和停止。非到达状态不伪造五状态。
- **P_F（五状态保护）**：保留P_B全部公共底线，额外读取同一原始特征产生的正式五状态及持续Deviation，由既有策略触发局部Recovery。不是关闭S/K时顺带改写原始保护输入。
- 保护输入的valid、spatial、temporal、距离/进展及时间先统一计算；到达开关只组合ArrivalGate资格。P_B/P_F是单独、明确的策略因子。

| 主组 | 运输推进判据 | 保护 | 可归因内容 |
|---|---|---|---|
| A_fixed | 当前目标模拟Applied后固定等待1.2s，到期请求下一步；不生成虚假的视觉ArrivalEvent | P_B | 固定时间运输＋共同安全底线，不冒充历史纯开环A |
| B_single | 与S2 B_single_frame相同：G+C0，单帧，无Q/W/S/K到达门 | P_B | 单帧视觉策略包；Q仍在公共保护通道计算 |
| BTQ | G+Q+W+C0 | P_B | 等稳定窗口反馈，非完整五状态策略 |
| F_full | G+Q+W+S+K+C0；采用同一冻结目标窗 | P_F | 完整到达门＋五状态保护策略包 |

四组均使用相同P0源准备；A只在运输推进上固定时间，不绕过源准备或公共安全。B→BTQ同时增加Q/W，不能独立归因W；W证据优先引用S2已完成的BQ诊断，不在S3无限加方法。

**桥接2×2因子表**：到达门{BTQ,F_arrival}×保护{P_B,P_F}。主组已包含BTQ/P_B和F_arrival/P_F，再加F_arrival/P_B与BTQ/P_F两组。固定P_B或P_F比较到达门；固定到达门比较保护。主比较若有收益但同保护下无差，则结论为完整策略收益，不能写成S/K到达优势。反作用后输入分叉是合理结果，所有桥接仍使用相同外生seed和预算。

若两个保护策略在正常条件相同输入前缀下产生不同非预期行为，先回归排错；不能把实现不一致当算法贡献。

## 4. 共同实验条件与控制预算

- 路径固定190→191→192→172，3计划运输步；420模板、48px/pitch，地图与ROI来源如实标注，非Gerber毫米实测。
- 候选基础配置沿用当前模型：dt0.01s、总预算24s、速度1.5pitch/s、响应延迟0.18s（delayed按模型1.15s）、Applied延迟0.04s、20fps、曝光0.008s、处理0.04s及0.015s抖动。不得为A或F单独调参。
- G为eta_target≥0.85、eta_source≤0.08；强组W至少5帧/0.25s、gap0.18s、质心跨度0.11pitch、覆盖跨度0.15。Q/S/K及C0沿用S2 v1语义，尤其保留缺帧后K历史首帧边界，不在S3中悄悄修复。
- P0所有组同源覆盖/位置/稳定窗，源准备超时2.6s；仅同source/transport定义可比较。独立记录P0是否使用Q及其当前可靠性语义，不能用目标门改写源门。
- 公共保护候选阈值沿用现有配置：无进展1.4s、最长尝试2.6s、无可靠观测1.8s、局部Recovery等待2.6s。实际字段与EventController映射在G0核对后冻结，不放宽失败阈值。
- 每运输循环最多2次目标Retry，每计划步最多1次局部Recovery。现有语义在Recovery源确认后用一次Retry恢复运输并重置循环计数，因此上界须分账：前后循环常规Retry合计≤4，Recovery后恢复运输≤1，Recovery命令≤1，加初始目标激活≤7次模拟Applied/步；超限为基础设施/契约错误，不默默继续。最终上界以G0对当前控制器逐分支核对为准；若源码反例否定该上界，先修订研究预算说明而非改生产控制器。
- 四组具有相同**可用预算**而不是强制相同实际动作次数。额外Retry/Recovery计入时间和动作代价，不能奖励停止早或恢复次数多。
- 只在相应模拟Applied成功后推进控制状态、重启尝试时钟；目标等待期间保持active，pending期间不继续出新事务。最后Complete若不产生物理命令，不伪造Applied。

## 5. 场景与最小机制验收

| 场景 | 拟检验问题 | 负对照/限制 |
|---|---|---|
| normal | 无额外保护需要时的完成与延迟代价 | 强方法不被要求一定优于A；保持全部计划步 |
| delayed | 固定等待与真实响应延迟不匹配 | 不能把较迟模拟Applied与较迟运动响应混同 |
| partial_stall | 参考未到达时是否过早更新；Retry能否按模型恢复 | 首尝试故障会在重试后解除是模型假设；failure为持续故障负对照 |
| jitter | P0源准备瓶颈与目标证据失败分别多少 | 端到端失败保留；另做受控运输诊断，不挪进端到端成功分母 |
| dropout | 截止前未确认、晚确认、无观测保护与重建窗口 | 同帧号缺失过程；不能按已处理帧重新抽噪声 |
| deviation | 五状态保护与到达门增量的区分 | 必做2×2桥接；Recovery数量本身不是收益 |
| failure | 真实模拟不达时安全停机及预算边界 | 不删除失败，不给“所有方法都失败”的条件伪造成功曲线 |

不直接将S2远端碎片/伪Mask作为已验证物理形变。若S3桥接场景中S/K仍不改变事件，保留“该模型下不可辨识”；不为追求F胜出扩展压力条件或筛seed。

模拟执行延迟当前为确定0.04s。若未来加入抖动，必须预声明按(step,attempt,command_role)索引的独立流，不复用算法RNG或按“第几次所有命令”强行配对。本轮不增加该功能。

端到端四组在P0阶段应有相同动作/捕获/观测前缀及源确认或源失败时间，逐项hash对齐。source_only可从共同前缀导出，不作为额外独立重复。transport_only使用声明的受控起点，不读GT替算法做源确认；主要用于jitter/dropout中区分源瓶颈与目标瓶颈，单独分母。

## 7. 事件、独立参考及终止语义

每计划步固定(step_id,source,target)，attempt/epoch随接受动作变化；请求行与Applied行通过request_id关联。真值保存world.active、goal、response_at、速度、有效任务/attempt、请求pending状态；每帧保存曝光、world采样、可用与处理时间及观测epoch。

独立参考基准仍为内部位置半径0.09pitch、速度≤0.06pitch/s、驻留0.15s完成区间[l,u]；预测只读模拟Mask和任务信息。先从连续truth计算各电极的物理驻留段与退出时刻，再按有效目标激励归属到计划步/运输episode；确认时刻还须处于相应物理支持段内，不能使用已经离开的旧到达事件。

同目标Retry若没有改变active/目标且位置、速度、驻留连续，不能只因软件attempt/epoch改变就清空物理参考；清空的是算法证据窗，不是独立物理真值。Recovery改激励回源、真实目标改变或truth断档时禁止跨段拼接；仅软件epoch改变先检查物理/激励连续性，而非机械重置。旧v2按epoch派生参考的实现仅作历史兼容，不直接作为新S3正式评分器。仅接近某目标但尚未属于有效Applied任务，也不补成该步运输支持。

对视觉或定时推进事件，分别在**请求时刻**与**新事务模拟Applied时刻**评价此前当前目标的独立支持。即使模拟Applied时才有支持，也不能追认请求时已经安全。以已发生驻留支持定义unsupported_at_request；只有在已实现同一有效任务参考且可比较时，才另分premature/timing_uncertain。主动切换截断未来时，不能用“如果继续等会到达”的反事实把unsupported改成确定提前。

最终到达/Complete也要独立评分。S3不沿用S2固定教师4s窗口及1s随访作为统一成功定义；控制本身会改变任务终点和观察机会。另报有参考却预算内未确认、记录缺失删失、无物理到达、未尝试，不能把全部未到达都叫识别漏检。

互斥trial终止结果，按下列优先级判定：

1. infrastructure_invalid：数据缺失/契约破坏，保留全部计划分母并报告，不能直接删除重抽seed；
2. source_preparation_failed：未通过共同P0，后3计划步均未尝试；
3. transport_aborted：进入运输但流程未完成（保护Stop/时间/动作预算等分别给stop_reason）；
4. workflow_complete_without_supported_path：流程结束，但任一步请求无独立支持/源参考不符/最终参考不符；
5. reference_supported_path_complete：源准备与独立源支持、3步有效推进、全部请求支持、最终支持及预算均满足。

错误事件、Unknown、Retry、Recovery是并行标签，不占终止类别。transport_complete只是流程完成布尔量，不等于第5类。
