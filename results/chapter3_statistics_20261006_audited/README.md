# 第三章批量仿真

本模块只调用现有PC规划和调度代码。不连接串口或相机，不改STM32，不改第二章策略，不新增CBS、强化学习、time-expanded A*或调度器变体。

## 运行

```powershell
python scripts/run_chapter3_statistics.py
```

配置位于`configs/chapter3_statistics.yaml`。默认20个固定seed，每档液滴数2、4、8、12、16、20、24、30；门宽20、7、3；故障数0、1、2、4、6、8、10。

默认生成时间戳目录；明确指定`--output`时拒绝已有目录，避免覆盖。`--repeats`可覆盖重复次数并写入manifest。快速验证可以使用`--repeats 1`，不得将单seed结果当成正式统计。

## 四组设计

### A：三种方法对照

与B共享任务，主图选8滴、20个seed，避免额外挑选优势案例。

- Static A*参考：每个储液池固定3步释放间隔，无跨来源时间协调。统计潜在违规，而不是物理碰撞。
- Safe serial参考：按给定任务顺序逐滴执行；保护已占据目标邻域，必要时重算空间路径。不成功表示该参考顺序不可执行，不宣称所有串行顺序都不可达。
- Coordinated：直接调用生产函数`build_multi_droplet_assignments`，保留Wait、排序、绕行和批处理兜底。

三个方法的源目标配对相同。生产兜底可能再次分配来源，生产成功时参考方法使用其最终配对；生产未输出完整方案时使用初始greedy配对。原始记录标明`reference_pair_origin`和`assignment_changed_by_fallback`。这是一组控制时序策略的对照，不是三种独立assignment算法的比较。

规划耗时使用实际调用时钟：生产方法记录完整调用；参考方法记录初始greedy分配耗时加参考路线生成耗时。它们不是相同内部调用次数，不能据此断言单个scheduler内核速度更快。审计、画图和保存不计入规划耗时。

### B：液滴数量扩展

8个储液池，每个沿用生产默认5滴容量。每个seed先打乱间距为两格的目标候选池，所有规模使用嵌套前缀，并共用20个静态障碍。目标互不相邻，排除图案合并策略，使审计针对独立运输。目标与障碍不重叠，源入口不会直接被障碍封住。

随机性来自目标子集、目标顺序、障碍和固定seed。该生成器是一个明确的独立目标任务分布，不代表所有自由放置或密集图案任务。不可达或无法预约的任务不重抽，不从分母删除。

### C：通道宽度干预

4个固定来源、8滴、相同错位障碍和同seed目标。只改变中部通道的开放宽度20、7、3；所有目标均在通道下方。宽门不是完全独立路径，只是相对较低的瓶颈约束。

报告Wait、最大释放延迟、makespan、等待占比、空间长度和静态空间路径重叠。空间重叠定义为核心格上经过该格的路径数n所形成的n(n-1)/2之和，计pair-cells；不是同时占据冲突，也不是独立拥塞强度的唯一指标。门宽变化也可能改变路径长度，不能只根据标签预设等待必须单调增长。

### D：运行时故障数量及位置

每个seed使用同一8滴窄门名义任务，在所有滴已经释放且任务未完成的真实全局时刻截取状态。未完成滴保留当前格，已完成滴保留目标格；不把已经存在的滴用None隐藏。

两类故障使用相同数量档位：random是在合法核心格上均匀洗牌；path_critical优先洗牌选择剩余原计划路径上的格，不足时才补其他格。记录实际命中剩余路径的数量，不声称每个关键故障都一定阻塞整条通道。每个seed的故障集合采用嵌套前缀，便于比较数量变化。

故障不取当前格、目标格或已有障碍。本实验验证中途通路失效，不覆盖直接损坏液滴当前电极/目标电极的所有情况。

增加同状态零故障重规划控制。主图路径比为`剩余长度/零故障重规划剩余长度`，主图makespan差也以零故障重规划为参照。另存对原scheduled_path剩余makespan的差值及生产函数的无故障最短剩余路径比，避免混淆。

同一个seed的零故障控制在两种故障位置类别中复用；不能把两类零故障记录合计成40次独立重复。

## 成功及统计口径

成功必须同时满足：目标数与ID无遗漏；轨迹沿现有图的合法边移动；不穿越障碍或故障；延迟释放后不消失；每滴从正确当前位置启动；已完成滴保持；独立安全审计没有vertex、edge-swap、当前spacing、transition-spacing违规。

每个液滴对和每个时间步最多计一种安全违规，按上述顺序分类。完成滴持续占据目标，未释放滴不计占据。`C`是冲突pair-steps，不是实物碰撞数或不重复事件数。

失败分类保留：`assignment_unreachable`、`unreachable_or_unschedulable`、`reference_unreachable`、`unsafe`、`unreachable`、`protective_pause`、`invalid_replay`等。程序返回success但轨迹身份或几何不正确，也不计成功。

- 每组成功率分母为全部20个配置seed，给出Wilson 95%区间。
- 故障任务若名义规划不可用，记`nominal_unavailable`。另给`eligible_n`与`success_rate_given_eligible`，区分整条管线成功率和可执行名义任务条件下的恢复率。
- 连续量使用样本均值及样本标准差，误差棒不是均值置信区间；只有一条有效样本时标准差为空。
- 安全完成makespan只统计通过审计的方案，每项都有独立`metric_n`。不能跨方法忽略成功样本差异直接比较条件均值。
- unsafe参考的理论时间线另存`nominal_timeline_steps`，不填进有效完成makespan。
- 规划/重规划耗时保留所有实际尝试，包括失败；失败的绕行率、完成步数等不可定义量保持空，不填零或无穷大。
- 释放延迟不是Wait。等待占比按`N_wait/(L_total+N_wait)`计算，不包含None释放延迟。
- 静态总长度计图边，不计毫米；故障时总长度只计未完成部分。makespan是离散步，不是实物秒数。

## 产物

- `图片/`：集中放A、B、C、D四张统计图，不新增演示截图。
- `records.csv`、`records.jsonl`：逐次运行记录，包含失败。
- `summary.csv`、`summary.json`：每条件的样本数、均值、标准差、成功率、区间及失败分类。
- `failed_replays.csv`：生产返回成功但审计不通过的记录，不从总体结果删除。
- `traces.jsonl`：原始任务、源目标配对、每种完整路径/调度、故障状态、返回轨迹和身份错误诊断，便于复现。
- `manifest.json`：seed、配置快照、当前Git提交、相关实际文件SHA256、Python版本、平台和时间。文件哈希包含未提交代码，因此不能只用Git HEAD复现。

可只重绘已有统计，原始数据和运行manifest不变：

```powershell
python scripts/run_chapter3_statistics.py --plot-from results/chapter3_statistics_20261006_audited
```

重绘另存`plot_manifest.json`，记录绘图代码及输入summary的哈希。

## 当前基线的限制

批量运行已经发现，运行时故障触发生产fill-batch兜底时可能重新分配已有滴的起点：目标仍配给原ID，但路径从其他滴当前位置甚至储液池重新出发。返回状态可能为success，却不满足身份连续性。本批次以`invalid_replay`记录，保留原始轨迹作为失效分析证据；此次没有修改生产算法来隐藏该现象。

因此不能把现有运行时重规划描述为在所有任务中都已正确保持身份。原单案例通过不替代批量边界验证。该问题的修复应作为后续独立、带回归测试的最小修改，再以同seed比较前后结果，而不是更换算法架构。

本阶段未实现assignment消融或scheduler内部消融。先分析A-B-C-D；现有结果不证明全局最优、一般分布上的必然优势或实物闭环成功。
